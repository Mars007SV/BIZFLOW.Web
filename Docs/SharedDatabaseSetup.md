# 🤝 Налаштування спільної бази даних (Optional)

## Коли це потрібно?

Якщо кілька користувачів Windows на **одному комп'ютері** мають працювати з **одними даними**.

---

## ⚠️ Важливо розуміти

### Стандартна поведінка (зараз):
```
👤 User1 → Своя база → Свої товари
👤 User2 → Своя база → Свої товари
```

### З спільною базою:
```
👤 User1 ──┐
           ├─→ Одна база → Спільні товари
👤 User2 ──┘
```

---

## 📝 Спосіб 1: Спільна папка

### Крок 1: Створіть спільну папку
```powershell
# Створити папку доступну всім користувачам
New-Item -Path "C:\BIZFLOW_Shared" -ItemType Directory

# Дати права всім користувачам
icacls "C:\BIZFLOW_Shared" /grant Users:F
```

### Крок 2: Змініть appsettings.json
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=C:\\BIZFLOW_Shared\\bizflow.db"
  }
}
```

### Крок 3: Змініть Program.cs
Закоментуйте код з user-specific path:

```csharp
// Замість цього:
// var userDataPath = GetUserDataPath();
// var dbPath = Path.Combine(userDataPath, "bizflow.db");

// Використайте:
var dbPath = @"C:\BIZFLOW_Shared\bizflow.db";
var connectionString = $"Data Source={dbPath}";
```

### ⚠️ Обмеження:
- Тільки один користувач може працювати одночасно
- Потрібні права адміністратора для створення спільної папки

---

## 📝 Спосіб 2: Мережева база (SQL Server)

Для справжньої багатокористувацької роботи з одночасним доступом.

### Вимоги:
- SQL Server або PostgreSQL
- Змінити з SQLite на SQL Server

### Приклад connection string:
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=BIZFLOW;Trusted_Connection=True;TrustServerCertificate=True;"
  }
}
```

### Зміни в коді:
```csharp
// В Program.cs замінити:
builder.Services.AddDbContext<BizFlowDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection")));
```

### Додати пакет:
```powershell
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
```

---

## 📝 Спосіб 3: Один Windows користувач

Найпростіший варіант для спільної роботи.

### Рішення:
1. Створіть один обліковий запис Windows (наприклад "BizFlow")
2. Всі працюють під цим користувачем
3. В BIZFLOW створіть різних користувачів:
   - Менеджер
   - Касир
   - Адміністратор

### Переваги:
- ✅ Не потрібно нічого змінювати
- ✅ Всі бачать одні дані
- ✅ Можна давати різні ролі в BIZFLOW

### Недоліки:
- ⚠️ Всі мають доступ до одного Windows користувача

---

## 🔄 Повернення до окремих баз

Якщо ви налаштували спільну базу і хочете повернутися:

### Крок 1: Відновіть код в Program.cs
Розкоментуйте:
```csharp
var userDataPath = GetUserDataPath();
var dbPath = Path.Combine(userDataPath, "bizflow.db");
var connectionString = $"Data Source={dbPath}";
```

### Крок 2: Видаліть спільну базу (опціонально)
```powershell
Remove-Item "C:\BIZFLOW_Shared\bizflow.db"
```

### Крок 3: Перезапустіть
Кожен користувач отримає свою базу знову.

---

## 💾 Міграція даних

### Якщо хочете перенести дані з однієї бази в іншу:

```powershell
# Експорт з SQLite
sqlite3 source.db .dump > backup.sql

# Імпорт в іншу SQLite базу
sqlite3 target.db < backup.sql
```

## 🎯 Рекомендації

### Для домашнього використання:
→ **Залишити окремі бази** (поточна конфігурація)

### Для малого бізнесу (2-3 людини, один ПК):
→ **Один Windows користувач** + різні користувачі в BIZFLOW

### Для середнього бізнесу (5+ людей):
→ **SQL Server** або **PostgreSQL** (вимагає розробки)

### Для великого бізнесу:
→ Мережеве рішення з клієнт-серверною архітектурою

## ❓ Поширені питання

**Q: Чи можна працювати одночасно з SQLite?**  
A: Ні, SQLite підтримує лише одне з'єднання для запису.

**Q: Чи зберігаються дані при зміні користувача Windows?**  
A: Так, кожен користувач має свою незалежну базу.

**Q: Чи можна об'єднати бази кількох користувачів?**  
A: Так, але потрібен скрипт для злиття даних.

**Q: Що швидше - окремі бази чи спільна?**  
A: Окремі бази швидші, бо немає конкуренції за доступ.
